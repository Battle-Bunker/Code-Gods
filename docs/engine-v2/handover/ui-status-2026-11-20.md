## What a future session should know

- **The 14 November UI rewrite differs from production.** Production lived on `main`: `src/dock`, `src/shell`,
  `src/core/panels`, `src/core/replay`. The rewrite on develop: `src/dock`, `src/panes`, `src/replay`. Differences:
  - Production's replay was a page-level mode (`ReplayGame`) with its own controller and a stored-or-paged replay file.
    Develop's replay is a **view state** (`ViewState.replay`, the `replay.*` affordances, stored per player per room on
    the server). So "is this game in replay" is the runtime context `"replay"`, derived from `view.replay?.gameId`
    (`core/affordance-runtime.tsx` replayContext), not from the URL.
  - Production derived the Timeline-for-assistant swap only for display (`withTimeline`). Develop needs the same trick
    inside `shownPanes` and `keepShown` (lib/v2-client panels.ts `standsIn`). Every new plan (open, close, move) must
    respect it.
  - Production's game codes were 4+ character Crockford prefixes. Develop's games have `code` = `<room>-<number>`, and
    test fixtures use other formats, so resolve by room and number, never by parsing `code`.
- **The dock code**
  - `shownPanes` merges a phase's defaults back in under several conditions: an arrangement from another phase, one
    lacking the defaults, a stored `results` pane. Each rule has bitten once (built: the results rule in replay,
    #1226). Read it fully before adding a pane that appears in more than one phase.
  - Pane plans are sequences of view writes, run one after another from the client. Any extra write is a race with
    the human's next click (#1235).
  - The desktop dock compares the drawn arrangement with the stored one (`sameDock`) to tell a human's gesture from its
    own drawing. Anything that changes sizes at draw time breaks that unless both sides are compared in drawn form
    (on the unmerged branch).
- **The e2e suites** (`artifacts/player-web/e2e`)
  - They are not run by CI. Several were stale against the owner's 17 Nov layout until #1226.
  - Each takes minutes. Run one per change, against `pnpm --filter @workspace/engine dev` (wait for `[dev] READY`;
    the first start may need `pnpm install` and a retry of the Convex binary download).
  - `SKIP_DEPLOY=1` reuses the uploaded build. Rebuild after any app change, or the browser runs old code.
  - v1-harness suites mark known gaps with `missing([...])` xfails tied to `docs/engine-v2/v1-parity.json`; flip both
    together.
- **Tooling**
  - The local Convex backend redeploys functions on every engine file save. Do not edit engine files while a browser
    suite runs.
  - `seedGame` (convex/v2/testing.ts) takes fixture options (`practice`, `code`, `bound`, `contested`) for e2e.
  - A game in a preset that pays to read serves the player's value from `v2Knowledge`, not `v2ObjectValues`. A new
    value field needs both paths (`tell()` in knowledge.ts and its call sites in loop.ts and ops/object.ts).
- **First-move latency** (seen narrowly: one local Lines · beginner game, two practice partners and a Simple agent).
  Offers start at 0.8 s of world time. Every seat's first move is at about 11.5 s, because the starters' `saving()`
  helper skips until 10 s of income is held (`SAVE_SECONDS = 10` in lib/v2-sandbox/guest helpers). This is a setting,
  not wiring.
