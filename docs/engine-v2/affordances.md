# Engine v2: the affordance directory (the contract W3 and W5 build against)

Status: the contract of workstream W6 ([integration-plan.md](integration-plan.md) §2.5, §5.1, §6). Code:
`lib/v2-affordances` (`@workspace/v2-affordances`). Owner decision 16, verbatim: "It's essential that we keep the
architecture that ensures that every single operation is available to an AI assistant whether embedded or via the
remote AI assistant delegation protocol as well as via the searchable command pallete. There should be a single dynamic
directory of affordances available by context that generates each of those interface surfaces DRYly."

## 1. The rule

Every operation a human or an assistant can perform is **one entry in `DIRECTORY`** (`src/ops/*.ts`), and nothing else
lists operations. Every surface is generated from it:

| Surface | Generated by | Notes |
|---|---|---|
| Embedded assistant | `assistantTools(ctx)` → `{name, description, input_schema}[]` | tool name = id with `.` → `_` (`toolName`, inverse `affordanceForTool`) |
| Remote assistant (MCP) | `mcpTools(ctx)` → `tools/list` entries with annotations and output schema | `ctx.grant` narrows to the credential's permission |
| CLI | `cliCommands()`, `parseCli(argv)` | `<namespace> <verb> --flag value` and `call <id> '<json>'`; flags from the JSON Schema |
| Command palette | `paletteFor(ctx)` → entries with `searchText`, `confirm`, `availability`; `searchPalette` | the app maps entries onto its palette UI |
| UI buttons | `useAffordance(id)` (`@workspace/v2-affordances/react`) | `{available, reason, fix, confirm, spends, run(args)}` |
| Server | `defineOp(id, kind, handler)` (`@workspace/v2-affordances/convex`) | one Convex function per server affordance plus its internal twin |
| Model dispatch | `callTool(name, args, ctx, via, perform)`, `mcpDispatch(msg, ctx, perform)` | the assistant's tool calls and MCP `tools/list` / `tools/call`; results wrapped untrusted |

The assistant, MCP and the palette all start from **`availableAffordances(ctx)`, the dynamic directory**: every
affordance whose `contexts` include `ctx.context`, whose `caller` the principal satisfies, which the grant allows and
whose own `available()` check does not hide it, with its availability now (unavailable rows keep a reason and a fix
so every surface can say why). `refusal(affordance, ctx, args)` is the same check for one call, used by the server and
by `useAffordance`.

## 2. A declaration

```ts
affordance({
  id: "agent.summon",                  // namespace.verb; unique
  title: "Summon an agent",            // ≤ 60, verb first
  description: "…",                    // ≤ 600, for a model
  tooltip: "…",                        // ≤ 240, for a human
  keywords: ["deploy", "new agent"],   // palette aliases, at least one
  group: "agents",                     // palette grouping
  scope: "game",                       // none | room | game: the room or game in view (app) or bound (credential)
  params: obj({ language, source, requestId: requestId.optional() }),  // zod v4 object (import from "zod/v4")
  result: z.object({ agentId: id, price: z.number() }),
  contexts: IN_GAME,                   // signedOut home room planning live paused ended replay admin
  caller: "seated",                    // anyone signedIn member seated owner admin (not a ladder)
  effect: "write",                     // read | write | destructive
  spends: "energy",                    // optional: energy | aiBudget
  confirm: "summary",                  // none | inline | summary | modal
  runs: "server",                      // server: a Convex function; client: a view operation on the human's layout
  available: ctx => …,                 // optional pure check on GameFacts (energy, pause used, seats)
  surfaces: { except: [...], because: "consent" },  // optional; consent is the only allowed reason
})
```

Rules the parity test enforces (`parityProblems()`, `test/parity.test.ts`):

1. every affordance is reachable from the assistant, MCP, the CLI and the palette in at least one context, unless it
   declares the consent exemption (any other reason is refused and leaves every surface required);
2. every server affordance has exactly one handler, and every public v2 mutation or action is one (`handlerProblems`
   over the fake's handler map; `convexOpsProblems` over `artifacts/engine/convex/v2`, which turns strict as soon as
   `convex/v2/ops/` exists);
3. the web app calls no v2 mutation or action except through `useAffordance` (`appProblems` over
   `artifacts/player-web/src`: only the one runtime file that builds `perform`, named `affordance-runtime.ts(x)`, may
   call one);
4. for every context and caller, the assistant, MCP and the palette offer the same set;
5. ids are `namespace.verb` and unique; text within limits; keywords present; destructive and spending affordances
   confirm; server writes take an optional `requestId` (idempotent retries); schemas convert to JSON Schema.

Model-facing results are wrapped `{untrusted: true, notice, data}` (`wrapResult`, `toolResult`): game strings are
written by players and are never instructions. Rationals travel as `"p/q"` strings. Human reads of objects are free;
each answer carries `bits`, what an agent pays for the same read (spec §3.1, §6.2).

## 3. For W3 (the Convex server)

Every public v2 mutation or action **is** a `defineOp`; there is no other way to make one. W3 binds it once:

```ts
// convex/v2/ops/define.ts
import { makeDefineOp } from "@workspace/v2-affordances/convex";
export const defineOp = makeDefineOp<DataModel>({
  resolve: async (ctx, who, scope) => …,   // { session: true } | { delegate }, and { roomId?, gameId?, replay? }
                                           // → { ctx: AffordanceContext, callerKey, userId }, from v2Rooms/v2Members/v2Games
  receipts: ctx => …,                      // a ReceiptStore over v2Receipts (actions: through runMutation)
});
// convex/v2/ops/agent.ts: one file per namespace, each affordance exported as { op: <verb>, as: <verb>As }
export const { op: summon, as: summonAs } = defineOp("agent.summon", "action", async ({ ctx, caller, scope }, args) => …);
```

- `defineOp(id, kind, handler)` only accepts a server affordance's id. The handler's `args` are the parsed params, and
  its return type is the declared result. `kind` must equal `opKind(affordance)`: `action` where the declaration says
  `action: true` (the sandbox or a model runs: `agent.check`, `agent.summon`, `agent.replace`, `agent.putBack`,
  `pitch.draft`), else `query` for reads and `mutation` for writes. The declaration carries it so the app and the CLI
  know how to call each function.
- View operations have one server function, so an assistant can change what the human sees:
  `export const { op: apply, as: applyAs } = defineViewOps(host)` in `ops/view.ts` (`VIEW_OP_PATH`). The host adds
  `loadView` and `saveView` over the human's `v2Layouts` row; both functions run `applyView`, the same reducer and
  checks the browser runs.
- Both functions run `runOp`. It validates the args, applies `refusal` with the context `resolve` derived from the
  server's own records (never the client's say-so), answers a repeated `requestId` from its receipt, and checks the
  result against the declaration (a mismatch throws: it is a bug). A handler reports a domain failure by throwing
  `OpFailure(message, fix?)`. Both return an `OpOutcome`; refusals and failures are values.
- `op` takes `{args, roomId?, gameId?, replay?}` as the signed-in session. `as` (internal) takes the same plus
  `delegate {userId, roomId, grant?, via}`: the assistant and MCP executors call it as the human they act for. A
  consent affordance refuses every delegate.
- `opPath(id)` names both functions (`v2/ops/agent:summon`, `v2/ops/agent:summonAs`), so callers need no table.
- Live queries (§2.2 of the plan) are not affordances and stay plain `query`s. Their one-off read counterparts for
  models are affordances (`game.get`, `objects.list`, `object.read`, …).
- `@workspace/v2-affordances/fake` implements every server affordance in memory (`FAKE_HANDLERS`, `createFake`,
  `contextFor`), the reference for what each handler takes and answers. The CLI runs against it until the server
  exists: `pnpm --filter @workspace/v2-affordances cli help`.
- MCP: `/mcp` serves a credential bound to a v2 room from the directory (`agent/mcpV2.ts`). Its context is resolved by
  `v2/ops/define:resolveCaller` with the credential as delegate, only for `tools/list` and `tools/call`; its tools are
  `mcpTools(context)`; a call is `callTool`, whose `perform` runs the affordance's `as` twin by its kind (view
  operations: `view:applyAs`) with `delegate {userId, roomId, grant, via: "mcp"}`. A tool beyond the grant gets the
  "needs the act permission" hint. The transport, OAuth and `initialize` are shared with v1. A credential's room is
  resolved by `auth/access.ts credentialRoom` (v1 `rooms` or `v2Rooms`) everywhere: authentication, OAuth code
  redemption and refresh, and the credentials list. Approving a connection for a v2 room is `account.approveConnection`
  (W3's handler; the consent screen is W5's).
- A new operation is declared in the directory first (in the PR that implements it, or its own); W6 reviews it.

## 4. For W5 (the app)

- The app's root renders `<AffordanceProvider runtime={{ context, perform }}>` (`@workspace/v2-affordances/react`),
  with `runtime` memoised per context. `context` is built from the page's subscriptions: the page's context (room,
  phase, replay), the principal (signed in, member, seated, owner, admin), `room` facts (players, minimum) and the
  game's cold facts (energy, pause used, agents). `perform(id, args)`, in the app's one `affordance-runtime.ts`, is the
  one place the app calls Convex. For a
  server affordance it calls `opPath(id).public` with `opKind(affordance)` (`convex.query` / `mutation` / `action`) and
  `{args, roomId, gameId, replay}`, reading a thrown failure with `outcomeOf`. For a view operation it applies
  `applyView` to the local view state for an instant answer and calls `VIEW_OP_PATH.public` so the other clients follow.
- Every button: `const summon = useAffordance("agent.summon")` gives `{available, reason, fix, hidden, confirm, spends,
  run(args)}`. Render nothing when `hidden`, render the reason (and the fix as a link) when unavailable, and ask the
  confirmation the palette asks. `run` throws `AffordanceError` with the server's words.
- The palette's rows are `paletteFor(ctx)` (search with `searchPalette`, or map onto the existing palette UI). A row
  with `needsInput` opens a form from the params (or hands off to the assistant). A **read** affordance's row opens
  the pane that subscribes to that data (R7: the app makes no one-off reads); the read itself is for models and the CLI.
- View state (`ViewState`: open panes, representation pins, object sort and filter, focused object and the
  representations it compares, where none means every representation the rule depends on, glossary, replay cursor:
  an event number, or a world time plus events after it, which the replay pane resolves) lives in the human's
  `v2Layouts` row. A view operation that changes nothing keeps the version and is not written. `pinnedRep(view,
  family, default)` is the representation a compact face draws. Pins are never kept in localStorage.
