# Isolated computational runtime adapters

This package owns no server, database, authentication, transport or game rules.
All three languages run in WebAssembly on Node's own V8, with no child processes:
Python is CPython 3.15 (WASI) hosted by `engine/python.mjs`, TypeScript is
QuickJS (`engine/quickjs.mjs`) behind the TypeScript 5.9.3 compiler
(`engine/typescript.mjs`), and Haskell is MicroHs (WASI) hosted by
`engine/haskell.mjs` (see "Haskell" below). `GameRuntime` (index.mjs) is the asynchronous,
bounded pool to use from a request handler or a Convex action; the engines
themselves are synchronous and have no admission queue.

## Setup (pinned)

Install workspace dependencies from the committed pnpm lockfile. This package pins
TypeScript 5.9.3 and quickjs-emscripten 0.31.0 (the TypeScript engine refuses any
other compiler version). Python needs one build artifact, the **runtime bundle**:

```
pnpm --filter @workspace/game-runtime setup:python    # pinned CPython WASI download (python3, stdlib only)
pnpm --filter @workspace/game-runtime build:python    # dist/python-runtime.bin.gz, checked against its pin
pnpm --filter @workspace/game-runtime setup:haskell   # pinned MicroHs commit (git) + wasi-sdk 25 (curl, tar)
pnpm --filter @workspace/game-runtime build:haskell   # dist/haskell-runtime.bin.gz (about 30 s), checked against its pin
pnpm --filter @workspace/game-runtime test
pnpm --filter @workspace/game-runtime benchmark
```

`setup:python` verifies the SHA-256 of the exact CPython 3.15.0 WASI SDK 33 archive
before extracting into the ignored `.cache/code-gods/python-3.15.0` directory.
`build:python` (scripts/build-python-bundle.mjs) checks the pinned `python.wasm`
(SHA-256 `9f58ad34…`), applies the reactor transform (engine/reactor.mjs: exports
the C APIs the host calls and every global as `snapshot_global_<i>`, rejects table
mutation instructions and non-function imports, caps linear memory at 128 MiB),
whose output is pinned (`REACTOR_SHA256`), and packs it with the trusted guest
code (`python/boot_guest.py`, `sandbox_guest.py`, `astbits_guest.py`,
`ast_bits_v1.json`) and the bundled standard library into one reproducible file
(19.6 MB, 5.2 MB gzip). Its SHA-256 is pinned in `engine/bundle.mjs`
(`PYTHON_BUNDLE_SHA256`); the runtime refuses any other bytes. After an intended
change to the guest code, run `build:python --pin` and commit the new pin. Workers
do not download anything themselves: the bundle comes from the `assets` option
(default: the built file next to the package). A missing or mismatched bundle is
`UNAVAILABLE`, never native execution.

Workers start from `generated/worker-source.mjs`, a single-string build of
`worker.mjs` and `engine/*` (`pnpm --filter @workspace/game-runtime build:worker`;
`test` fails if it is stale), so they also work where this package is bundled into
other code, as in a Convex action.

## Integration

An **agent** is ordinary code that defines `agent(obj)` and returns a list of
mutator calls built with the constructors of the room's trusted, per-instantiation
**prelude** (generated by `lib/game-types`, `PreludeParts`). The runtime knows no
object type: everything type-specific is in the prelude, and the host parses and
validates what comes back.

```ts
import { createRuntime, RuntimeError } from "@workspace/game-runtime";
const runtime = createRuntime({ language: "python", workers: 2, queueLimit: 32 });
const parts = objectType.prelude(inst);              // lib/game-types PreludeParts
const settings = {
  objectType: "Int", wireMaxLength: 0,               // 0 for numeric types
  interactionComputeMs: 1000, stepBudget: 500000,    // CPU backstop; deterministic step budget
  prelude: { key: parts.hash, python: parts.python, js: parts.js, dts: parts.dts,
             pricing: { python: vocab, typescript: vocabTs } },   // see "Prelude contract"
};
const source = "def agent(n):\n    return [add(1)]\n";
await runtime.inspect(source, settings);
// {complexityFunctionId: "ast-bits-v1", cost, astBytes: 11, parts: {structure, names, literals, moveFlags},
//  literalMoves: [["add", {"k": 1}]], literalMoveFallbackBits: [...]}; never evaluates the source
await runtime.act(source, 41, settings, seed);  // seed: 64-bit decimal / 0x-hex string, per act
// {calls: '[["add",{"k":1}]]' (UNTRUSTED text), usedRandom: false, steps: 2}
await runtime.validate(source, [0, 10], settings, [seed0, seed1]);
// {inspection, acts: [ActResult, ActResult]}; each sample gets a fresh guest
runtime.close(); // shutdown hook: rejects outstanding work, kills workers
```

TypeScript source: `function agent(n) { return [add(1)]; }` (annotations allowed).
`runtime.grammarId` is `python-agent-v1` or `typescript-agent-v1` (`GRAMMAR_IDS`).

### Pool options

`createRuntime({ language, workers, queueLimit, deadlineMs, startupMs, prepareMs, execution, assets, typescriptFiles, compilerIdleMs })`
(index.d.ts documents each):

* `execution: "worker"` (default): each engine runs in a `worker_thread`. A hard
  wall terminates a worker that is stuck past its deadline, for example inside one
  long native step such as `sum(range(10**9))` or a catastrophic regex, and the
  pool replaces it. A Python worker restarts from the shared snapshot in ~100 ms,
  with no second bootstrap. `"inline"`: one engine on the calling thread,
  requests one at a time, **no hard wall**. The step budget and the
  post-execution CPU check still apply, but a native step that never returns
  blocks the thread. Neither QuickJS's regex engine nor CPython's `re` polls an
  interrupt. Use inline only for trusted code or measurement.
* TypeScript in worker mode is **one compiler worker** (type-check, transpile,
  price; the TypeScript compiler is most of the memory) plus `workers`
  **QuickJS-only execution workers**. Compiled output is trusted and is cached in
  the pool (LRU, 128 entries / 4 MiB), so an act of a known source never waits
  for the compiler. The compiler worker stops after `compilerIdleMs` (default
  60 s) idle and restarts on the next new source.
* Python: `workers` engines. The first one bootstraps CPython into the
  initialized snapshot (~0.6 s); the rest start from that snapshot. The compiled
  reactor and the snapshot are shared by all workers of the process.
* `assets` (Python): the bundle's bytes, a file path, or an async loader. It is
  loaded, verified and compiled **once per process per source** (`loadPythonRuntime`).
  `typescriptFiles` (TypeScript): the files of `typescript` and
  `quickjs-emscripten` to load. The runtime never imports them by package name,
  so a bundler cannot inline them. The default is `typescriptPaths()`.
* `warm(n)` starts engines ahead of demand; `close()` rejects outstanding work and terminates workers.

### In a Convex Node action

`artifacts/engine/convex/runtime/node.ts` holds warm module-scope pools and the
asset hook. `pnpm --filter @workspace/engine upload-runtime` stores the bundle in
file storage (`runtimeAssets`). Each warm instance fetches it once, caches it in
`/tmp`, and verifies the pin:

```ts
"use node";
import { bindRuntime, runtimeFor } from "../runtime/node";
export const tick = internalAction({ args: {...}, handler: async (ctx, args) => {
  bindRuntime(ctx);   // the Python bundle loads from storage through this action's context
  const { calls, usedRandom, steps } = await runtimeFor(settings.language).act(source, input, actSettings(settings), seed);
} });
```

**`act` returns the exact ASCII string the guest's `__encode_calls` produced**
(at most 64 KiB), unparsed. The host must `JSON.parse` it as `MutatorCallWire[]`,
enforce `MAX_CALLS`, validate every call with the type's mutators and re-validate
the resulting object with its codec. Samples in `validate` do not prove anything
about other inputs; every later act runs again and is validated again.

`RuntimeError.code` is one of `CONFIG` (bad options/settings, or a prelude that
does not compile, run, decode or type-check), `COMPILE` (the player's source
breaks the grammar or the type check), `DOMAIN` (an input that is not a wire
value; an encoder result that is not an exact ASCII `str`/string primitive),
`EXECUTION` (the player's module, `agent` or the encoder raised; the message
carries the guest's own `Name: message`, with the line in Python),
`LIMIT` (compute/memory/stack/wall limits; an encoded result over 64 KiB),
`CAPACITY`, `UNAVAILABLE`. Never take cost from execution. Associate inspection
results with the exact source, language, grammar id and prelude key on the
authoritative server.

### Settings

`{ objectType, wireMaxLength, interactionComputeMs?, prelude: { key, python, js, dts } }`;
other fields (a full room settings object) are ignored and never sent to workers.

* `objectType`: `/^[A-Za-z][A-Za-z0-9_]{0,63}$/`, used only in cache keys.
* `wireMaxLength`: 0–1024. An input is valid if it is a safe integer, or an
  ASCII string of at most `wireMaxLength` characters. No other check: the host
  validates objects with the type's codec. No coercion, wrapping or truncation.
* `interactionComputeMs`: integer 1–1000, default 5: the CPU backstop (not deterministic; see
  "Determinism"). Open agents should run with a generous value (1000) so the deterministic step
  budget binds.
* `stepBudget`: integer 1–10,000,000, default 500,000 (docs/open-agents.md §1.3).
* `prelude.key`: 1–128 printable ASCII characters (`PreludeParts.hash`).
  `python`, `js`, `dts`: NUL-free, well-formed UTF-8, at most 64 KiB each; the
  whole IPC request (with the 16 KiB source) must fit 512 KiB.
* `prelude.pricing`: `{python: PricingVocab, typescript?: PricingVocab}` (index.d.ts), the
  game-specific half of the summon-price tables; `typescript` defaults to `python`.
* `act`'s `seed`: a 64-bit unsigned integer as a decimal or `0x` hex string, supplied by the
  host for every act (see "Determinism").

## Grammar

**python-agent-v1.** A module (`exec` mode) with exactly one top-level
`def agent(...)` that accepts one positional argument (`def agent(grid):`;
extra parameters need defaults; `*args` is allowed; not `async`). Other
top-level statements are allowed: helper defs, classes, constants, assignments,
imports of the preloaded computational modules. They run at act time, inside the
budget. Inspection parses and compiles but **never evaluates** the player's source.

**typescript-agent-v1.** A script whose top level declares
`function agent(...) { ... }` once (not async, not a generator, no imports,
exports, `import()` or reference directives). It is type-checked (strict,
ES2022 library plus `performance.now()`, TypeScript 5.9.3) together with the
prelude's `dts` and a trusted check `__encode_calls(agent(__decode(wire)))`, so
`agent` must accept what `__decode` returns and return what `__encode_calls`
accepts. An unannotated first parameter of `agent` is typed as
`ReturnType<typeof __decode>` (other unannotated parameters are strict-mode
errors). Types are then erased and QuickJS runs the JavaScript.

**haskell-agent-v1.** A module body without a `module` header: optional
`import` lines, then declarations, one of them `agent :: Obj -> [Call]` (or an
unannotated `agent` of that type). The engine compiles it as module `Agent`
after `import Room` (the room's generated helpers, lib/game-types `haskell.ts`)
and `import Prelude hiding (...)` for the Prelude names the room redefines
(String's `reverse`, `truncate`), so the room's names win; `Prelude.reverse` and
`Data.List` stay reachable qualified. `Obj` is the room's object (`Int`,
`String`, or `Grid` with `Cell` records); `Call` is a move. Diagnostics give the
player's own line and column.

## Haskell (MicroHs on WASI)

**Bundle.** `setup:haskell` fetches MicroHs (Apache-2.0) at a pinned commit
(`git`, then SHA-256 of the files the build reads) and wasi-sdk 25 (SHA-256 of
the release archive) into `.cache/code-gods`; `build:haskell` compiles MicroHs's
evaluator twice for `wasm32-wasip1` (with the compiler's combinator image, and
alone) and packs both with the precompiled `base` package into
`dist/haskell-runtime.bin.gz` (1.2 MB gzip), pinned by
`HASKELL_BUNDLE_SHA256` (engine/haskell-bundle.mjs). `wasi/config.h` and
`wasi/extra.c` replace MicroHs's unix platform files (no terminal, signals,
sockets, directories or processes; sleeping returns at once). eval.c is patched
at build time (`patchEval`): a reduction budget checked every 10,000 reductions
(the scheduler slice), exit code 86 when it is spent, and two exports for the host;
bfile.c's LZMA compressor becomes the identity (`patchBfile`: the encoder needs
about 190 MB), so compilation caches are written uncompressed. Both modules import
their memory (16 MiB initial); `extra.c`'s `sbrk` grows it past `__heap_end`.

**Compile** (one compiler worker, output cached by the pool like TypeScript's):
the player's `Agent`, the room's `Room` and a fixed `Main` (`getContents`,
`cgDecode`, `agent`, `cgEncode`, `putStr`) become one self-contained combinator
program (6M-cell heap, about 95 MiB of wasm memory; the compiler has a
2·10⁹-reduction ceiling and the pool's preparation wall). The room's first
compilation writes a MicroHs compilation cache (`-CW`, about 12 MB, kept per room
by prelude digest in the compiler worker, 4 rooms / 64 MiB); later ones read it
(`-CR`) and skip compiling `Room`. On V8: 4.5–7 s for a room's first compilation
in a worker, then about 1.3–1.8 s (2.8–3.4 s before the cache). The program is
byte-identical either way; a cache the compiler cannot use is replaced, and a
cache over 32 MiB is not kept.

**Compile and execution pools apart.** `role: "compile"` makes a pool that only
compiles (`compile(source, settings)` → `{inspection, js}`), and
`compilation: "external"` an execution pool with no compiler, which runs only such
programs (`actCompiled`). The engine (artifacts/engine) compiles in an action of its
own (`runtime/haskellCompile.ts`), which stores each program
(`haskellPrograms`) for every other action; the actions that run agent pools never
hold the compiler (about 250 MiB) beside them, and on one instance whichever is used
closes the other's idle pools. On a cloud Node action (512 MiB, a fraction of a
vCPU) a room's first compilation took about 37 s and an act about 150 ms; the
compile pool's wall is 120 s and it stays warm 5 minutes.

**Memory.** Each module has one linear memory per thread, zeroed and reused by
the next run (fresh memories pile up faster than V8 frees them): always for the
compiler, and for the evaluator while it is at most 32 MiB. A Haskell-only pool
(compiler and evaluator worker) peaks at about 490 MiB RSS locally, about 340 MiB
steady.

**Act** (execution workers): a fresh evaluator instance runs that program with
the wire value on stdin (the number in decimal, or the text) and a 2M-cell heap;
its stdout is the moves as JSON (`[["slide", [{"__hs": "row", "args": [2]}]]]`,
or `{"commit": "if-improves", "calls": [...]}`). The room's trusted JavaScript
constructors, in QuickJS, turn each move into the wire call exactly as a
TypeScript agent's call would (`movesProgram`): only the room's move helpers and
area helpers may be named. A Haskell agent's calls equal a TypeScript agent's for
the same moves (test/haskell.test.mjs).

**Determinism and steps.** Single-threaded graph reduction with a fixed heap is
deterministic; the WASI host (engine/haskell-wasi.mjs) answers only the virtual
clock and the act's seeded byte stream, a read-only tree, stdin/stdout/stderr and
writes under `/out/`. One step is 10 reductions; the budget is checked every
10,000 reductions and exactly at the end. Running out of heap (or the Haskell
stack) is `LIMIT`; an uncaught exception is `EXECUTION`. Node's own `node:wasi`
is not used (its fast path crashes on these modules).

**Price: hs-token-bits-v1-uniform.** Over the token stream of the player's
source (engine/hs-token-bits.mjs): a token kind (log2 7), then keyword/special
class, line breaks by indentation (Elias gamma), names alpha-equivalent with
standard Haskell names (`hs-standard-names.json`) and the room's names as
externals, literals by the universal codes, and the move flag per use of a move
helper. The grammar's own signature line `agent :: Obj -> [Call]` is free. No
literal moves (Haskell moves are coded like other expressions). Uniform and
approximate like ts-ast-bits, and not calibrated against Python: a one-move agent
costs about 52 bits (TypeScript 47, Python 30, before their literal moves); the
realistic Grid agent of benchmark.mjs about 1,800 (TypeScript 1,760, Python 760).

## Summon price: ast-bits-v1 (Python) and ts-ast-bits-v1-uniform (TypeScript)

One interface for both languages: `inspect` returns the description length of
the **player's source only** (never the prelude) in bits, by part, and the
literal moves it found. The host completes the price:

```
summon bits = cost + Σ_i ( host accepts literalMoves[i]
                             ? MOVE_FLAG_BITS + log2(#mutators available) + D(literalMoves[i])
                             : literalMoveFallbackBits[i] )
cost        = parts.structure + parts.names + parts.literals + parts.moveFlags
```

`D` is lib/game-types' `decisionBits` (grid-lab `Mutator.describe_bits`).
`astBytes` (the old ast-bytes-v1 integer price) is still returned, for
comparison only.

**ast-bits-v1** (Python; docs/open-agents.md §2.1, grid-lab branch
`claude/gridlab-open-agents`) is computed inside the guest during trusted
inspection by `python/astbits_guest.py`, a faithful port of grid-lab's
`astbits.Walker` in "code" mode: preorder over the `_fields` of the
CPython 3.13 grammar in the tables, node classes drawn from corpus-weighted
p(class | parent, field) with `<end>`/`<none>`, identifiers coded by scope with
alpha-equivalence (LEGB, comprehension and class scoping, walrus, `global` /
`nonlocal`, slot 0 = `agent`), externals at P_EXT = ½ (½ corpus builtins + ½
uniform API), attributes / keywords / modules from published vocabularies with a
spelled escape, the universal literal codes (Elias gamma, the 98-symbol string
code with the API string vocabulary at p = ½, the 18-symbol float code), and a
literal-move flag at Q_MOVE = ⅛ on every call. The game-independent tables are
`python/ast_bits_v1.json`, copied from grid-lab and pinned by SHA-256
`e965947993720ce41eb308ec2cc36c1950ee5a3689405139f3d9a75cbe0f1200` (the worker
refuses any other bytes). The game vocabulary (API names, attributes, keyword
parameters, strings, which names are mutator / area constructors) comes with the
prelude as `pricing`, because our API names (`paint`, `recolour`, `swap_cells`,
`row`, `column`, ...) are not grid-lab's.

*Literal moves.* A call whose callee resolves (through the scopes: a user
function named like a constructor is not one) to an API mutator constructor,
with only literal arguments (constants, tuples / lists of them, ±numbers,
non-callable API constants such as colour names, area constructors on literals),
is evaluated by the **trusted prelude constructors** inside the guest (the
arguments are literals and the code is the room's), encoded with the prelude's
`__encode_calls` and returned as a wire call. The guest charges nothing for it;
it returns the bits the same call costs coded as an ordinary call (flag false +
its fields) as the fallback, for a call the host finds invalid. Every spelling of
the same move (`paint_row(2, "red")`, `paint(row(2), red)`, the raw `move(...)`)
gets one price.

*Test vectors.* `test/python-host.test.mjs` runs the 17 programs of grid-lab's
`test_vectors.json` (copied to `test/ast-bits-v1-vectors.json`) with a
grid-lab-vocabulary config and prelude, under both schemes: `structure`, `names`
and `literals` match to 1e-5 bits (all 17 × corpus and uniform, in the pinned
CPython 3.15 guest); `astBytes` matches `ast_bytes`; programs without literal
moves match grid-lab's `moves` with `moveFlags`, and so their `total` with
`cost`; the four spellings of one move are detected as the same wire call
(`["paint", {"colour": 0, "kind": "line", "region": [0, 2]}]`), whose
log2(#available) + D the host adds. A program the 3.13 grammar tables do not cover
(for example a 3.14 template string) is a `COMPILE` error.

**ts-ast-bits-v1-uniform** (TypeScript, `ts-ast-bits.mjs`) is a principled but
**approximate** analogue: there is no TypeScript grammar table or corpus in the
spec. It uses the same structure (preorder; uniform choices over the node kinds
of the slot's category: statement, expression, type, binary operator, modifier,
class member, object member, binding name, with an end marker in node lists;
other slots implied by their parent cost 0), names by scope with
alpha-equivalence (file and function scopes; externals = ES2022 globals ½ + API
½), property names (½ API attributes + ½ the frozen ES2022 member list
`ts-ast-bits-es-members.json`, SHA-256
`162d1a5d0df96ed4d49632f334d177c7e8bdd48fd0f15efd0777a920c104da2b`, with a spelled
escape), the same literal codes, and the same literal-move flag and detection
(evaluated by the trusted JS prelude in a separate QuickJS context). **Gaps:** no
corpus weights (so it is higher than Python's corpus price for the same
program); absent optional children are not coded (it is not a strict prefix
code); categories come from node kinds rather than a per-(parent, field)
grammar; block scopes are flattened to their function. Prices are comparable
within TypeScript rooms, not across languages.

## Prelude contract

The prelude is trusted text from `lib/game-types` (`PreludeParts`); its Python
and JS parts must both define, at top level:

* `__decode(wire)`: the wire value (safe integer or ASCII string) → the kid-API
  object passed to `agent`.
* `__encode_calls(calls)`: the agent's return value → an ASCII JSON string of
  `MutatorCallWire[]`. Expected to raise on malformed calls.
* the read helpers and one constructor per available mutator.

`pricing` (see "Settings") lists, per language, the prelude's public names: all
API names, the attributes of the objects it hands out, the constructors' keyword
parameters, the strings the API gives meaning to, and which names are mutator and
area constructors. Mutator constructors must be pure functions of their
arguments (they are called on literal arguments during inspection) and should
raise on invalid arguments.

`dts` must type-check on its own and declare `__decode` and `__encode_calls`
with the types above (e.g. `declare function __decode(wire: string): Grid;`,
`declare function __encode_calls(calls: readonly MutatorCall[]): string;`) plus
every public helper/constructor. Prelude top-level names share the guest's
global namespace with the player's code (`def agent(grid): return [swap(...)]`).
Encoders should capture what they use at prelude time (e.g.
`const __STRINGIFY = JSON.stringify`, `_DUMPS = json.dumps`), so ordinary player
code cannot break them by accident; this is a convenience, not a boundary.

### One act

| Step | Python (CPython WASI on V8) | TypeScript (QuickJS) | Budget |
|---|---|---|---|
| compile | prelude and player module compiled by the trusted compiler in a pristine guest; marshal bytes cached | type-check + transpile in the compiler worker; output cached in the pool | outside (3 s / startup wall) |
| fresh guest | restore the one initialized snapshot; fresh agent builtins and import proxies, a private `Random(seed)`, the virtual clock and a seeded entropy stream restarted; fresh globals | fresh runtime and context; virtual `Date` / `performance`, seeded `Math.random` | outside |
| prelude | prelude code `exec`'d into those globals | prelude script evaluated | outside |
| decode | `obj = __decode(input)` | `obj = __decode(input)`; `__encode_calls` captured | outside |
| player | player module executed in the same globals; its code objects counted by `sys.monitoring` | player script evaluated; interrupt ticks counted | **inside** |
| agent | `agent` looked up in globals, `calls = agent(obj)` | `agent` read from the global object, called | **inside** |
| encode | `__encode_calls` looked up again (the guest owns its globals), called | captured `__encode_calls` called | **inside** |
| result | exact `str` (type identity, no subclass), length ≤ 65536, UTF-8 copy, ASCII | string primitive, length ≤ 65536, copied through a captured `JSON.stringify` (exact, NULs included), ASCII | **inside** |

The encoder is **untrusted-equivalent**: the player can monkeypatch it, the
constructors, or anything they use (`json`, `JSON`, prototypes), or build call
dictionaries by hand. The worst outcome is an invalid string (rejected by the
host) or a call list they could have returned anyway. No repr/str/JSON hook is
invoked on the host. Error text for `EXECUTION` is computed by guest code inside
the budget and read back as an exact, length-capped string.

### Cache keys

Engines cache only trusted compiler output and inspection results, keyed by
the grammar id, the complexity id (and, in Python, the pricing scheme), the object
type, `prelude.key`, a SHA-256 the worker computes over the exact prelude text
and pricing vocabulary (`[python, js, dts, pricing]`), and the exact source
(TypeScript also keys on its version and compiler options). A host that reuses a key for
different text therefore cannot get a stale compilation. Python caches compiled
preludes (`("prelude", key, digest)`) and player modules in one LRU
(128 entries, 4 MiB including keys); TypeScript caches compilations (128 entries,
4 MiB) and self-checked prelude declaration files (16 entries); in worker mode the pool keeps
its own copy of the compiler worker's output under the same key (128 entries, 4 MiB), so
execution workers receive only trusted JavaScript. Results are never cached.

## Script mode (python-script-v1, typescript-script-v1)

A second programme type beside the agent, for analytics (the assistant's `run_code`;
docs/assistant/code-execution.md): a **script** defines `main(data)` and returns JSON. The host passes
`data` as JSON text; nothing else reaches the guest.

```ts
const r = createRuntime({ language: "python" });
const { result, output, outputTruncated, usedRandom, cpuMs } =
  await r.script("def main(data):\n    return sorted(data['xs'])[:3]\n", JSON.stringify({ xs: [3, 1, 2] }), { cpuMs: 10000, seed: "7" });
// result: '[1,2,3]' (JSON text, ASCII, UNTRUSTED); output: what print / console.log wrote
```

| | Python | TypeScript |
|---|---|---|
| engine | the same pinned CPython-WASI bundle and initialized snapshot as agents: the script guest (`engine/python-script.mjs`) is trusted text compiled after the snapshot restore, so the bundle pin and every agent result are unchanged | the pinned TypeScript 5.9.3 erases types (`transpileScript`: syntax errors located, types never checked; imports, exports, `import()`, modules and reference directives refused), QuickJS runs it |
| modules | the agents' preloaded modules (math, statistics, collections, itertools, functools, operator, json, re, decimal, fractions, random, time, hashlib) plus bisect and numbers, as read-only proxies; no numpy | ES2022 built-ins; no Intl, Node, DOM, timers or modules |
| captured text | `print` | `console.log` / `info` / `warn` / `error` / `debug` (non-strings as JSON) |
| budget | CPU post-check, then the pool's hard wall (nothing interrupts a Python loop): `cpuMs` + 1–5 s, the worker is terminated and replaced from the snapshot (about 100 ms) | QuickJS's interrupt handler stops at `cpuMs`; the hard wall covers one long native call |
| memory | 128 MiB of linear memory (MemoryError → `LIMIT`) | 128 MiB QuickJS heap, 1 MiB stack |

**State: an object store, no files.** `options.store` is JSON text `{scope: [key | "prefix*"], objects: {key: value}}`
(≤ 4 MiB): the owner's objects the host loaded for this run. The guest's global `store` reads them
(`store.get(key, default)`; a key outside the scope raises `StoreError`), buffers `store.put` / `store.delete`
(JSON values, or bytes as `{"$hex"}`; keys of `[A-Za-z0-9_./-]`, none under `runs/`), and lists them
(`store.list(prefix)`). A successful run returns its writes as `writes`, JSON `{put: {key: value}, delete: [key]}`
(≤ 2 MiB). They are UNTRUSTED: the host validates and commits them (artifacts/engine/convex/code/objects.ts). A failed
run returns none. There is no file system: the WASI host denies every file import after bootstrap, `open` and the
file modules are absent in Python, and QuickJS has no `std` / `os`.

Both: a fresh guest per run, the virtual clock from 2026-01-01T00:00:00Z, `random` / `Math.random` seeded by
`seed`, `usedRandom` reported. `json.loads` / `JSON.parse` of the input is trusted and outside the budget; the
module, `main(data)` and the JSON encoding of its result are inside it. Non-finite numbers become `null`; a
result that is not JSON (a set, a function, a BigInt) is `EXECUTION`. Limits (`SCRIPT_LIMITS`): source 64 KiB,
input 4 MiB, result 1 MiB (else `LIMIT`), captured text 256 KiB (clipped, `outputTruncated`), CPU 10 s by default
and at most 20 s. Errors: `COMPILE` (syntax; TypeScript module syntax), `EXECUTION` (raised, with the line in
Python; no `main`; not JSON), `LIMIT` (CPU, memory, result size), `DOMAIN` (the input is not JSON text within the
limit), `CONFIG` (options). TypeScript pools cache transpiled scripts like agents' compilations; the compiler
worker serves both. Tests: `test/script.test.mjs`.

## Computational module inventory

`test/python-host.test.mjs` ("runner: calls, the standard library ...") executes
representative workloads in the actual pinned guest, not host Python. Verified: **math, itertools, functools, collections,
re, json, decimal, fractions, statistics, hashlib**. This is an inventory of
tested computational uses, not a promise of every API in those modules.
These modules, plus `ast`, `operator`, `random` and `time`, are preloaded during
trusted bootstrap. Lazy imports requiring a file read are unavailable once
submitted code starts, even if that file belongs to the bundled standard library.
This is a preloaded computational-module contract, **not full standard-library
filesystem access**. Agents see these 14 modules only (`import` of anything else
fails), as read-only proxies. Time is virtual and randomness seeded (see
"Determinism"); sleeping is unavailable. The builtins `open eval exec compile
input breakpoint globals locals vars id memoryview exit quit help` are absent and
`print` does nothing.
Native extensions not compiled into this build, pip packages, process creation,
networking, threads, writable files, host environment and host files are excluded.
No import-name blacklist is claimed as a security boundary.

TypeScript supports QuickJS ECMAScript computational built-ins, including strings,
arrays, maps, sets, JSON, Math, RegExp, a virtual Date and `performance.now()`, and
a seeded Math.random. Node, DOM, network, module loading, package imports and
timers are unavailable. The only installed host callbacks are the virtual clock
and the seeded generator.

## Determinism (docs/open-agents.md §1.3, §3.5)

The same (source, input, settings, seed) gives the same act result, in
measurement and in play, on every host:

* **Clock.** Every act starts at 2026-01-01T00:00:00Z and the clock advances
  1 µs per read. Python: the **host** answers WASI `clock_time_get` (all clock
  ids) with the virtual clock, so `time.time()`, `perf_counter()`, `monotonic()`
  and any escape past the proxies see the same instants. JS: `Date.now()` /
  `new Date()` (integer ms) and `performance.now()` (ms since the act started)
  share one tick counter. No sleep.
* **Randomness.** Python's `random` is a private `random.Random(seed)` (so an
  agent draws exactly what grid-lab's sandbox draws for that seed); `Random()`
  and `seed()` with no argument draw from that stream; `SystemRandom` is
  unavailable. WASI `random_get` (os.urandom past the proxies) is a SplitMix64
  stream from the seed, answered by the host. JS: `Math.random()` is SplitMix64
  (seed), top 53 bits / 2^53 (grid-lab's vector: seed 12345 → 2454886589211414944).
* **`usedRandom`** is true if the act drew from the seeded generator (Python:
  the proxy's flag; also any `random_get` the host saw during execution; JS: the
  host callback).
* **Steps: the deterministic bound.** Python: `sys.monitoring` LINE and JUMP
  events in the player's own code objects (not the prelude's); over `stepBudget`,
  a `BaseException` is raised at that event and every later one, so `except
  Exception` (or `BaseException`) cannot swallow it, and the act is a `LIMIT`
  ("Step limit exceeded"). Grid-lab's `full_greedy` uses 196k of the 500k
  default. JS: QuickJS's interrupt handler, polled every 10,000 ticks (calls and
  backward jumps), so the JS count has a 10,000-step granularity and includes
  prelude helper code the agent calls. Both counters are deterministic.
* **What changed with the move from Wasmtime to V8.** V8 has no instruction fuel,
  so the former second deterministic ceiling (2,000,000 Wasmtime fuel units per
  configured ms) is gone. The step budget is now the **only** deterministic bound
  in both languages. One step can contain arbitrary native work (`sum(range(10**9))`,
  big-integer arithmetic, one regex match, one `sorted` of a huge list), and only
  the CPU/wall backstops stop that:
  - a post-execution check in the engine: this thread's CPU time
    (`process.threadCpuUsage`, present in Node 22.22, which the local backend and
    Convex's Node 22 use; on a Node without it, this thread's wall time). Execution
    past `interactionComputeMs` is a `LIMIT`;
  - in worker mode, the pool's hard wall, min(`deadlineMs`, max(50 ms, 10 ×
    `interactionComputeMs`)) after the execute phase starts. It **terminates the
    worker** (`Worker.terminate()`), and the pool replaces it from the shared
    snapshot.
  When a backstop fires, the result is not deterministic. Open agents run with
  `interactionComputeMs: 1000`, so the step budget binds first for any agent that
  loops in Python or JS code.
* **No state** survives an act (snapshot restore / fresh context); the decimal
  context is reset; module attribute writes fail; `PYTHONHASHSEED=0`.
* **The initialized snapshot is identical on every host.** Bootstrap itself runs on
  the virtual clock and a fixed entropy stream, and reads the standard library
  from the bundle with directory listings in sorted order. CPython object
  addresses (`repr(object())`) are therefore reproducible everywhere. They differ
  from the former Wasmtime host's, whose heap layout depended on the host file
  system's readdir order; that was the only result difference the parity test
  found (see "Security gates").
* **Seeds** are the host's (`deriveSeed(salt, ["play", ...])` for play,
  `["measure", instKey, gridIndex, replicate]` for measurement). The salt must be
  a season secret, or an agent could recognise measurement seeds.

What remains outside the deterministic semantics: the CPU/wall backstops,
memory exhaustion near the 128 MiB (Python linear memory) / 32 MiB (QuickJS heap)
limits, and very deep **C-level** recursion in Python, which ends either at
CPython's own guard (`RecursionError`, deterministic) or at the V8 thread's native
stack (`LIMIT`, "Recursion too deep"), depending on the thread's stack size. A
given pool configuration always answers the same; inline (main thread, ~1 MiB
stack) and worker (4 MiB) can differ for such programs.

## Capability and state-isolation boundary

Submitted Python runs only inside the CPython WebAssembly instance; submitted
JavaScript runs only in a fresh QuickJS Wasm context/runtime. Neither is evaluated
by the host interpreter. Workers receive an empty host environment.

Trusted WASI startup (engine/wasi.mjs, "bootstrap" mode) uses synthetic
`PYTHONHOME=/` and `PYTHONHASHSEED=0`, no inherited descriptors (stdin is empty,
stdout and stderr are discarded), and a **read-only, in-memory** `/lib` holding
the bundled standard library. No host file is reachable at any time, and there is
no create, write, rename, link or delete operation. PYTHONHOME is removed from
guest `os.environ` afterward. After bootstrap, **every WASI import except
clock_time_get, clock_res_get and random_get is denied**: it returns
`ENOTCAPABLE`, or traps for `proc_exit`, which has no result. The three answered
imports come from the virtual clock and the act's seeded stream, never the real
clock or entropy. This covers bundled-file reads, writes, stdin/stdout, directory
and metadata operations, sockets, process exit and blocking poll. Import-name
filtering is not the boundary: recovered builtins face the same host-side
capability checks. Guest stdout is not a result channel. Results cross the C API
only as an exact `str` (type identity checked, at most 65536 characters, ASCII);
no attacker-provided repr/str/JSON hook is invoked for extraction.

The pinned CPython command module is converted to a reactor, offline (engine/reactor.mjs,
a port of the former reactor.py, pinned by SHA-256), by parsing standard Wasm sections
and its debug name map to expose existing C APIs, every global as an export, and a
128 MiB memory maximum (V8 has no store limits). An instruction decoder rejects table
mutation instructions and unknown proposals; imported tables, memories and globals are
also rejected. No table state can therefore change during execution. Before every
compilation, inspection and act, all linear memory and mutable globals are restored
from one trusted initialized snapshot. The snapshot is stored as its nonzero 4 KiB-page
runs (12.9 of 40 MiB in 28 runs). Restore copies those runs and clears any other page
that is no longer zero. A trap, a host fault, or a grown memory replaces the
instance (a fresh `WebAssembly.Instance` of the same compiled module) before reuse.
Builtins, modules, globals and heaps cannot retain mutations across calls or agents.

Compiled modules (player modules and room preludes) are cached as **trusted
compiler-produced marshal bytes**, never user-supplied marshal data. After
snapshot restoration, code is deserialized into fresh globals; the trusted
prelude runs first, then the player's module. The cache is LRU-bounded to 128
entries and 4 MiB including keys. There is no snapshot per source or per prelude.
Restoring the snapshot restores the real `random` module's state too; agents use
the per-act seeded proxy. Hash seeding is fixed.

QuickJS uses a fresh context/runtime per act. A TypeScript execution worker only
ever receives JavaScript produced by the trusted compiler worker. Seeded random APIs
are not a claim of cryptographic safety.

## Resource limits and capacity

* Source: 16 KiB UTF-8; each prelude part: 64 KiB; request: 512 KiB;
  input strings: 1024 characters; encoded calls: 64 KiB.
* `interactionComputeMs` defaults to 5 ms. Compilation, cache lookup, snapshot
  restoration, the trusted prelude and `__decode` are outside this budget (the
  preparation wall bounds them). Executing the player's module, calling `agent`,
  `__encode_calls` and extracting the result are inside it. The execution wall
  starts only after trusted setup.
* Python: 128 MiB linear memory (the module's own maximum; `MemoryError` beyond
  it), one initialized snapshot (40 MiB of memory, 12.9 MiB stored; 48 MiB maximum),
  and a separate 4 MiB / 128-entry code cache. Trusted preparation (compile,
  inspect, prelude, decode) has a 3-second wall in worker mode (`prepareMs`).
  Guest execution is bounded by `stepBudget` (deterministic), the post-execution CPU
  check and the execution wall (above). There is no fuel.
* QuickJS: 32 MiB heap, 512 KiB stack, interrupt checks (deterministic steps,
  then CPU) and an expiry post-check. Each engine runs a trusted warm-up act
  before announcing readiness, so V8's lazy compilation of QuickJS's Wasm is not
  charged to a player's first act. Long native builtins may return late; the
  worker wall terminates hard hangs.
* Workers report the start of the execute phase. The pool separates startup
  (default 30 s), preparation (`prepareMs`: 3 s for Python, startup for
  TypeScript) and execution hard walls (default cap 4 s). `terminate()` is a
  backstop, not a 5 ms real-time scheduling guarantee.
* Worker V8 old-space caps: Python 96 MiB, TypeScript compiler 192 MiB,
  TypeScript execution 64 MiB. These are not OS RSS quotas. Wasm memory, compiled
  code and the allocator are extra.
* One worker by default; maximum 16. Queue defaults to 32 waiting requests,
  capped at 1024. Queue waits expire; overload returns `CAPACITY`. Worker crashes
  reject the active call, and workers restart for queued work. Missing setup
  rejects queued work rather than respawning indefinitely.

## Measurements

The workload throughout is the realistic Grid agent `GRID_AGENTS` in
`benchmark.mjs`. It scans every row, column and diagonal, finds colour regions
with `grid.regions`, and makes two moves; about 190 Python steps. It runs on the
default Grid prelude (`objectType("Grid").prelude(inst)` with
`defaultSettingsFor("Grid", lang)`: 4×4, base10, rgb), with open-agent settings
(`interactionComputeMs: 1000`, step budget 500,000), a fresh seed per act, and
16 spawned grids. The host is a shared 4-vCPU container, with other agents' jobs
running (load average 1.4–3.1 during the runs).

## Security gates

The hostile regression suites, using the fixture prelude in `test/fixture-prelude.json`:

* `test/runtime.test.mjs` and `test/pricing.test.mjs`: the pool contract for both
  languages, including the TypeScript compiler/executor split, inline mode and
  the idle compiler.
* `test/python-host.test.mjs`: the former `python/test_reactor.py`,
  `test_runner.py`, `test_sandbox.py` and `test_astbits.py`, ported call for call,
  plus the V8 host's own checks. The WASI table denies everything but the virtual
  clock and seeded entropy; the 128 MiB cap holds; the pinned bundle is required;
  the worker watchdog terminates native work and restarts from the snapshot.
* `test/parity.test.mjs`: Python on V8 ≡ the former Wasmtime host. It replays 364
  requests from `test/parity/cases.json` against results recorded from
  `python/runner.py` (`test/parity/golden.json`). Those requests cover the
  fixture, all 17 ast-bits-v1 vectors under both schemes, literal moves, the
  universal codes, every object type's default prelude and a 5×5 rgby Grid with
  realistic agents, errors and limits. 349 are **identical**: calls,
  `usedRandom`, steps, every inspection bit, error codes and messages. The 15
  accepted differences are documented in the test. One is an old-host bug: an
  inspection over 2,000 bytes was truncated and failed. The other is a CPython
  object address.

Together they cover host file, network and process attempts (directly and past
the agent proxies via the real builtins module), invalid inputs and settings,
broken preludes, stdout forgery, state across acts, non-executing inspection,
budgeted player modules, a slow prelude/decode outside the budget, compilation
abuse, infinite loops, malicious regex, the virtual clock and seeded entropy
(also past the proxies), read-only module proxies, step budgets that `except
BaseException` cannot swallow, deterministic replays per seed, snapshot reset of
builtins, modules and prelude state, monkeypatched encoders and constructors,
malicious result hooks and str subclasses, non-string, non-ASCII and oversized
encoder output, embedded NULs, and cache keys across preludes (including a reused
key with different text, and a changed pricing vocabulary). They also cover the
ast-bits-v1 test vectors, literal-move detection and fallback, renaming
invariance, code-cache bounds, memory growth and the memory cap, the table
decoder, capacity failure and worker recovery. It is not a sandbox security audit.
Before public hostile multi-tenant use, independently audit both engines and
the host imports, test engine-version upgrades, and qualify memory and CPU on the
target host. QuickJS upstream does not claim a completed security audit. Do not
represent this package as formally verified or as permission to expose full
native Python/Node standard libraries.
